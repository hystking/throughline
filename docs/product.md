# Throughline — プロダクト定義 (PRD)

- Status: Draft
- 最終更新: 2026-08-03
- 対象読者: このプロダクトに関わる全員 (技術的な話は書かない)
- 技術設計は [`docs/design.md`](./design.md)

---

## 1. 名前

### Throughline

**throughline** — 物語や議論を貫いて流れる一本の筋。断片的な出来事をつなぎ、
「これは結局どういう話なのか」を成立させている線。

テックニュースは毎日大量に流れてくるが、そのほとんどは**点**として消費される。
昨日読んだ記事と今日読んだ記事がつながっていることに、たいてい気づけない。
このプロダクトは、その**線**を見せるためにある。

**タグライン: 「テックニュースを、線で読む。」**

---

## 2. ひとことで

> 毎朝5分。テックニュースを「点」ではなく「線」で読めるようにする、日刊ダイジェスト。

---

## 3. 解決したい課題

### 課題1: 点でしか読めない

「A社がモデルを値下げした」という記事を読んでも、
それが *先週B社が仕掛けた値下げへの対抗* であり、
*3週間前から続いている推論コスト競争の一局面* だということは、記事には書いていない。

一次情報は「今日起きたこと」しか語らない。文脈は読者が自分で組み立てるしかなく、
毎日追い続けている人以外には**不可能**。

### 課題2: 量が多すぎて、時間が足りない

Hacker News、Reddit、各社の公式ブログ、ニュースレター。
全部を追うのは非現実的。かといって週末にまとめて読むと、もう鮮度がない。

### 課題3: 「読んだ」と「使える」の間に距離がある

英語の記事を斜め読みして「なんかすごいらしい」で終わる。
自分の仕事にどう関係するのか、明日から何が変わるのかまでは、たどり着かない。

### 課題4: 会話のネタにならない

要約サービスは「何が起きたか」は教えてくれるが、
**現場がどう反応したか**、**専門家がどこにツッコんだか**は落ちている。
だから読んでも、人に話せるほどの厚みがない。

---

## 4. 4つの約束

Throughline は、読者に対して次の4つを約束する。
**すべての機能・すべてのコンテンツは、この4つのどれかに紐づいていなければならない。**

### ① 線で読める — ストーリーとナラティブを理解できる

- 各ニュースには「**この流れ**」がつく。
  例:「7/28 のA社値下げ → 7/31 のB社対抗、の3手目」
- キーワードごとに**時系列で流れを追えるページ**がある。
  「推論コスト」を選べば、この1ヶ月で何が起きたのかが1画面で読める。
- その日の記事群から**通底するテーマ**を抽出して、冒頭で提示する。

> これが Throughline の核であり、他の要約サービスとの決定的な違い。

### ② すぐに活かせる

- 各ニュースに「**明日から**」がつく。自分の仕事に何が効くのか、1〜2文で。
- 試せるものには、試せる場所へのリンクを添える (リポジトリ、ドキュメント、プレイグラウンド)。
- 「すごい」で終わらせず、「で、どうする」まで書く。

### ③ 他人に自慢できる

- 各ニュースに「**ここだけの話**」がつく。
  - Hacker News / Reddit で交わされた鋭い指摘や反論
  - 記事本文には書かれていない前提・裏話・数字の読み方
  - 「みんなが見落としているポイント」
- 昼休みに同僚に話したときに「詳しいね」と言われる密度をめざす。
- ただし**創作は絶対にしない**。実在するコメント・実在する事実のみ。

### ④ 数分で理解できる

- **1本 = 30秒。全体 = 5分。** これを設計上の制約として守る。
- 気になった1本だけ、さらに1分かけて深く読める構造にする。
- 網羅性より**取捨選択**。載せないことに価値がある。

## 5. 誰のためのものか

### 主ターゲット: 現役のソフトウェアエンジニア / テックリード

- 朝、コーヒーを淹れてから最初のミーティングまでの10分でキャッチアップしたい
- 技術的な深さは理解できる。噛み砕きすぎると逆に物足りない
- 「で、うちのプロダクトにどう効く?」を常に考えている
- チームに共有できるネタを探している

### 副ターゲット: プロダクトマネージャー / 技術に近い意思決定者

- 個別の技術詳細より**業界の流れ**を知りたい
- 「なぜ今これが話題なのか」を説明できるようになりたい

### ターゲットではない人

- 技術に触れたことのない一般読者 (専門用語をそのまま使うため)
- 網羅的な情報収集をしたい人 (取捨選択が前提のため)
- リアルタイム性を求める人 (1日1回の更新のため)

## 6. 扱う範囲 — テクノロジー全般

**AI に限定しない。** AI は最大の話題ではあるが、テックの一部でしかない。

| 扱う | 例 |
|---|---|
| AI・機械学習 | モデルリリース、推論基盤、エージェント、評価 |
| 開発ツール・言語 | 言語のリリース、フレームワーク、エディタ、ビルドツール |
| クラウド・インフラ | 各社の新サービス、Kubernetes、運用の知見、障害の教訓 |
| Web・ブラウザ | 標準仕様、ブラウザの新機能、フロントエンド |
| データ | データベース、データ基盤、分析 |
| セキュリティ | 脆弱性、インシデント、対策 |
| ハードウェア | チップ、デバイス、性能 |
| 業界・ビジネス | 買収、資金調達、組織、規制 |
| 研究 | 論文、ベンチマーク、新手法 |

**扱わない**: 消費者向けガジェットのレビュー、暗号資産の相場、企業のPR記事そのもの、ミーム。

> **配分の目安**: AI が半分弱、それ以外が半分強。
> 「今日は AI の話ばかりだった」という日があってもよいが、
> 「毎日 AI の話しかない」なら情報源の設定を見直す。

## 7. 一日の体験

```
07:00  更新される。

07:05  トップを開く。まず今日の見出しと3〜4文のリードを読む。
       ここで「今日は何の日だったか」がわかる。

07:06  「今日のテーマ」を読む。
       個別の記事に入る前に、通底する流れが1〜3個示されている。
       ここが Throughline のいちばんおいしいところ。

07:07  記事カードを上から流し読む。1枚30秒。
       重要度・カテゴリ・タグが見えているので、興味のないものは飛ばせる。

07:09  1本、気になったカードで手が止まる。
       「この流れ」を読んで、前回の続きだと気づく。
       タグをクリックして時系列ページへ飛び、1ヶ月分の流れを1分で追う。

07:11  「ここだけの話」を読む。HN のあのコメントが刺さる。
       これは昼に誰かに話そう、と思う。

07:12  閉じる。

12:30  昼休み。同僚に話す。「詳しいね」と言われる。 ← 成功
```

## 8. コンテンツの型

### その日のページ

| 要素 | 役割 | 対応する約束 |
|---|---|---|
| 日付・見出し | 今日を一言で | ④ |
| リード文 (3〜4文) | 今日の総括 | ①④ |
| **今日のテーマ** (1〜3個) | 記事をまたぐ流れ | **①** |
| 記事カード (最大12枚) | 個別のニュース | 全部 |
| 前日 / 翌日リンク | 連続性 | ① |

### 記事カード

| 要素 | 中身 | 対応する約束 |
|---|---|---|
| 重要度・カテゴリ・タグ | 飛ばす判断のため | ④ |
| 見出し (日本語) | 40字以内 | ④ |
| 要約 | 200〜300字。何が起きたか | ④ |
| ポイント (2〜4個) | 事実の箇条書き | ④ |
| **この流れ** | 過去のどの出来事の続きか。1文 + 前回へのリンク | **①** |
| **明日から** | 実務にどう効くか。1〜2文 | **②** |
| **ここだけの話** | 現場の反応・鋭い指摘・裏話 (最大3件、引用元リンク付き) | **③** |
| リンク | 元記事 / 一次ソース / 議論 / リポジトリ | ②③ |

### トピックページ (キーワード別)

| 要素 | 役割 |
|---|---|
| キーワード名と概要 | 何の話か |
| **時系列リスト** | いつ何が起きたかを縦に並べる ← **①の本体** |
| 勢い (伸びているか) | 今ホットかどうか |

### トレンドページ

- 直近30日で**伸びている**キーワード
- 各キーワードの推移が一目でわかる
- ここから各トピックページへ入る

## 9. 編集方針

### 載せるもの

- 実質のあるニュース。事実か、事実にもとづく分析
- 議論を呼んでいるもの (反応が面白いものは、それ自体が価値)
- 小さくても「効く」もの (地味なリリースが実務を変えることがある)

### 載せないもの

- 中身のない発表、企業のPRそのまま
- ミーム、煽り、低品質な質問スレッド
- **すでに載せたもの** (直近2週間は重複させない。ただし「続報」は別)
- 裏が取れなかったもの (確信度が低いものは、その旨を明示するか落とす)

### 絶対にやらないこと

- **反応やコメントの創作**。存在しない発言を作らない
- **記事にない数値・固有名詞の捏造**
- 一次ソースを読まずに書くこと
- 憶測を事実のように書くこと

> 不確かなものは「不確か」と書く。それが信頼につながる。

### トーンと文体

- 専門用語はそのまま使う (`inference`, `fine-tuning` を無理に訳さない)
- 断定できることは断定する。曖昧な逃げを書かない
- 煽らない。「衝撃」「ヤバい」は使わない
- 事実 → 意味 → 反応、の順で読ませる

## 10. 体験の原則

1. **速さが最優先** — ページは軽く、すぐ表示される。JavaScript を使わない
2. **読むことに集中させる** — 広告なし、モーダルなし、アニメーションなし
3. **一列に並べる** — 情報を探させない。上から下に読むだけで完結する
4. **すべてが読み物** — 検索やフィルタに頼らせない。編集で解決する
5. **どこからでも入れる** — 過去のどの日・どのトピックのページも、それ単体で意味が通る
6. **リンクは必ず本物へ** — 要約で完結させず、元記事へ送る責任を持つ
7. **暗いところでも読める** — 端末の設定に従う

## 11. スコープ

### v1 (まず作るもの)

- 毎朝1回の更新
- その日のページ / 過去日のページ / アーカイブ一覧 / RSS
- 記事カード: 見出し・要約・ポイント・**明日から**・**ここだけの話**・リンク
- 「今日のテーマ」(記事をまたぐ流れの抽出)

### v1.1 (①を完成させる。最優先の追加)

- **トピックページ** (キーワード別の時系列)
- **トレンドページ** (伸びているキーワード)
- 記事カードの「**この流れ**」(前回へのリンク)

> ①「線で読める」は Throughline の存在理由そのもの。
> v1 は「毎日ちゃんと出る」ことの検証に集中し、v1.1 で本丸に着手する。

### v2 以降の候補

- 週次まとめ (「今週の5本」「今週伸びた話題」)
- カテゴリ別ページ
- Discord / Slack への配信
- 独自ドメイン

### やらないこと

- 会員登録・ログイン・パーソナライズ
- コメント欄
- 広告・課金
- リアルタイム更新
- 多言語対応
- 記事本文の全文転載

## 12. 成功をどう測るか

### 一次指標 (これが満たされなければ意味がない)

| 指標 | 目標 |
|---|---|
| **毎朝ちゃんと出ているか** | 30日連続で更新される |
| **自分が毎朝読むか** | 週5日以上開く。開かない日が続くなら中身が悪い |
| **5分で読み切れるか** | 実測で5分以内 |

### 二次指標 (4つの約束が効いているか)

| 約束 | 測り方 |
|---|---|
| ① 線で読める | トピックページへの遷移率。「この流れ」が付いた記事の割合 |
| ② すぐ活かせる | 元記事・リポジトリへのクリック率 |
| ③ 自慢できる | **週に1回以上、ここで読んだネタを人に話したか** (自己申告) |
| ④ 数分で理解 | 滞在時間5〜8分に収まっているか |

### 品質のチェック (毎週、目で見る)

- 事実誤認がなかったか
- 創作された反応が混ざっていなかったか
- 「これは載せるべきだった」という取りこぼしがなかったか
- AI 以外の話題がちゃんと入っていたか

## 13. リスクと向き合い方

| リスク | 向き合い方 |
|---|---|
| **事実誤認・捏造** | 一次ソース必須。確信度を持たせ、低いものは明示または除外。週次で目視チェック |
| **AI の話ばかりになる** | カテゴリ配分を毎週確認。情報源の重みを調整 |
| **同じ話題が続いて飽きる** | 直近2週間の重複除去。ただし「続報」は①の価値なので別扱い |
| **要約だけ読まれて元記事が読まれない** | 要約で完結させない。「明日から」と「ここだけの話」で元記事へ送る |
| **外部サイトの悪意ある記述に引っ張られる** | 出力形式を固定し、検証を通す (詳細は設計書) |
| **運用コストが読めない** | 記事数・調査の深さを設定で絞れるようにしてある |

## 14. 用語

| 語 | 意味 |
|---|---|
| **Throughline** | サービス名。および「複数の出来事を貫く流れ」そのもの |
| **今日のテーマ** | その日の記事群から抽出した、通底する潮流 (1〜3個) |
| **この流れ** | 個別記事につく、過去の出来事とのつながり |
| **明日から** | 個別記事につく、実務への含意 |
| **ここだけの話** | 個別記事につく、現場の反応・鋭い指摘・裏話 |
| **トピック** | キーワード。これを軸に時系列で流れを追う |
| **重要度** | 1〜5。カードの読み飛ばし判断に使う |
| **確信度** | 裏が取れた度合い。低いものは印をつける |
